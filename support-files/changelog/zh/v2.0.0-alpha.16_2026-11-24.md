## [Version: v2.0.0-alpha.16] - 2026-11-24

Full Changelog: [v2.0.0-alpha.15...v2.0.0-alpha.16](https://github.com/infituit/opencode-acp/compare/v2.0.0-alpha.15...v2.0.0-alpha.16)

**发布范围**

- ACP 2.0 Alpha fork 压缩状态恢复更新，包含 [#80](https://github.com/infituit/opencode-acp/pull/80) 和 [#81](https://github.com/infituit/opencode-acp/pull/81)。

**新增功能**

- `/acp recover-fork`：预览已有空状态 fork 的恢复结果，不写入 ACP 状态或备份。
- `/acp recover-fork --apply`：先保存私有备份，再恢复可验证的来源压缩状态。
- `/acp recover-fork --rollback <backup-id>`：撤销该次恢复；状态发生后续变化时拒绝覆盖。

**缺陷修复**

- 新 fork 首次初始化时识别 `fork.sessionID`，不再将 fork 来源与 subagent 的 `parentID` 混淆。
- 来源读取遵循配置的存储位置和 fork 边界，并将压缩记录与可验证的冻结工具输出映射到 fork 的 ID，避免错误继承来源调用 ID。

**兼容性与升级前置条件**

- 要求 **OpenCode >=2.1.4 且 <3**。
- 不新增依赖或配置项，不改变既有会话持久化格式、message refs 或 compression block IDs；从 alpha.15 升级无需数据迁移。
- 已有空状态的旧 fork 不会自动修复，需先预览，再显式执行恢复。
- 恢复与回滚仅支持单 OpenCode 实例、空闲会话操作。备份包含会话状态和摘要，应妥善保管。

**已知问题**

- 已有 inactive/decompressed 记录、历史计数或不明确解压历史的会话不支持该恢复入口；来源不可用、边界缺失、映射不确定或嵌套块不完整时拒绝恢复。
- 本版不保证解决 [#34](https://github.com/infituit/opencode-acp/issues/34) 中全部长历史处理与服务恢复问题。
