## [Version: v2.0.0-alpha.13] - 2026-11-22

Full Changelog: [v2.0.0-alpha.12...v2.0.0-alpha.13](https://github.com/infituit/opencode-acp/compare/v2.0.0-alpha.12...v2.0.0-alpha.13)

**发布范围**

- ACP 2.0 Alpha 上下文安全维护更新，完善解压预算预检、近期消息压缩及紧急裁剪保护。

**缺陷修复**

- 解压前按实际可见消息投影估算文本与 reasoning 占用，并预留 completion 预算。预计增长且超出输入预算时，保持压缩状态与统计不变，提供可执行的 `toFile` 调用，引导关键词搜索与分段读取；不会自动写文件。
- 修复 `dangerous: true` 未绕过近期消息软保护的问题；工具／文件、最后用户消息、smart-plan 和质量检查仍然有效。
- 紧急裁剪跳过命中工具或文件保护规则的整条消息；sticky replay 不再将旧截断结果覆盖到当前受保护消息上。
- 紧急裁剪与 sticky replay 使用同一份 provider/model 生效配置，正确应用模型专属保护设置。

**兼容性与升级前置条件**

- 要求 **OpenCode >=2.1.4 且 <3**。
- 不新增配置项或依赖，不改变持久化格式、message refs 或 compression block IDs；从 alpha.12 升级无需数据迁移。
- `emergencyTruncation` 默认仍关闭；现有截断记录保留，取消保护后可继续按原有逻辑重放。

**已知问题**

- 解压预算为可见文本与 reasoning 的估算，不包含原生媒体的实际 token 成本，也不等同于 provider 的精确请求预算。
- 受保护内容可能使请求仍然超预算；保护规则不会恢复被宿主原生 compaction 或外部操作清除的内容。本版不代表 [#51](https://github.com/infituit/opencode-acp/issues/51) 的全部问题均已解决。
