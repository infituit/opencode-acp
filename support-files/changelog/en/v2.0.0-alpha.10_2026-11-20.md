## [Version: v2.0.0-alpha.10] - 2026-11-20

Full Changelog: [v2.0.0-alpha.9...v2.0.0-alpha.10](https://github.com/infituit/opencode-acp/compare/v2.0.0-alpha.9...v2.0.0-alpha.10)

**Release scope**

- An ACP 2.0 Alpha performance maintenance update reducing repeated token encoding for long histories and full-history reads during tool events.

**Improvements**

- Add a process-local LRU cache with up to 65,536 exact token counts, retaining only content fingerprints and counts, not original text. Changed content is recounted, and approximate fallback results are not cached.
- Resolve tool names from lifecycle events, avoiding full-history reads for this purpose during normal event sequences. Preserve history lookup and retries for missing events or evicted entries, without changing compression timing.
- Extend existing request-local diagnostics with counting paths, cache hits, misses, evictions, errors, and elapsed time. Offline summaries remain compatible with older records; input text and fingerprints are not logged.

**Compatibility and upgrade prerequisites**

- Requires **OpenCode >=2.1.4 and <3**.
- No new configuration options or dependencies, and no changes to persisted formats, message refs, or compression block IDs. Upgrading from alpha.9 requires no data migration.
- Preserve existing text normalization, special-token handling, failure fallback, and historical provider usage handling.

**Known issues**

- Cache hits still scan text to compute fingerprints; first-seen or evicted content still requires encoding. Concurrent sessions whose combined working set exceeds capacity may still cause repeated eviction. Cold-path speedups are not guaranteed.
- This release does not eliminate other history loading or all long-history delays, and does not include the image/base64 or decompression-budget fixes discussed in [#51](https://github.com/infituit/opencode-acp/issues/51).
