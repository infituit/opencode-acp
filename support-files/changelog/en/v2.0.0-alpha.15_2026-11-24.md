## [Version: v2.0.0-alpha.15] - 2026-11-24

Full Changelog: [v2.0.0-alpha.14...v2.0.0-alpha.15](https://github.com/infituit/opencode-acp/compare/v2.0.0-alpha.14...v2.0.0-alpha.15)

**Release scope**

- An ACP 2.0 Alpha maintenance update for long-history token-counting responsiveness, including [#78](https://github.com/infituit/opencode-acp/pull/78).

**Improvements**

- When provider usage is unavailable and token estimation must traverse history, request-time accounting yields to the event loop between messages instead of occupying the main thread for the entire count.
- Preserve existing accounting, caching, and failure fallback rules. Context nudges and final budget checks still wait for accounting of their respective current message projections.
- Add event-loop responsiveness metrics to the long-history replay for comparing accounting results and scheduling behavior.

**Compatibility and upgrade prerequisites**

- Requires **OpenCode >=2.1.4 and <3**.
- No new configuration options or dependencies, and no changes to persisted formats, message refs, or compression block IDs. Upgrading from alpha.14 requires no data migration.
- Historical provider usage, fork recovery, and accounting rules in optional emergency guards are unchanged.

**Known issues**

- Approximately 8 ms is a target time slice, not a hard latency limit. Encoding or serializing a single large message and other synchronous stages can still block the event loop. Cooperative scheduling does not guarantee lower total request latency.
- This release improves responsiveness during accounting; it does not resolve every issue tracked in [#34](https://github.com/infituit/opencode-acp/issues/34).
