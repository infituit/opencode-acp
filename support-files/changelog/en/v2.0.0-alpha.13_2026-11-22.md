## [Version: v2.0.0-alpha.13] - 2026-11-22

Full Changelog: [v2.0.0-alpha.12...v2.0.0-alpha.13](https://github.com/infituit/opencode-acp/compare/v2.0.0-alpha.12...v2.0.0-alpha.13)

**Release scope**

- An ACP 2.0 Alpha context-safety maintenance update improving decompression preflight, recent-message compression, and emergency truncation protection.

**Fixes**

- Estimate visible text and reasoning before decompression, reserving room for completion. When restoration would grow context beyond the input budget, leave compression state and statistics unchanged and provide an executable `toFile` call with guidance for keyword searches and partial reads. No file is written automatically.
- Fix `dangerous: true` failing to bypass recent-message soft protection. Tool/file, last-user-message, smart-plan, and quality checks still apply.
- Skip entire messages matching protected tool or file rules during emergency truncation. Sticky replay no longer overwrites currently protected messages with previously truncated output.
- Use the same effective provider/model configuration for emergency truncation and sticky replay, including model-specific protection settings.

**Compatibility and upgrade prerequisites**

- Requires **OpenCode >=2.1.4 and <3**.
- No new configuration options or dependencies, and no changes to persisted formats, message refs, or compression block IDs. Upgrading from alpha.12 requires no data migration.
- `emergencyTruncation` remains disabled by default. Existing frozen truncation entries are retained and can resume replay under the existing rules when protection is removed.

**Known issues**

- Decompression budgeting estimates visible text and reasoning; it excludes actual native media token costs and is not an exact provider request budget.
- Protected content may leave a request over budget. Protection does not restore content removed by native host compaction or external operations. This release does not resolve every issue tracked in [#51](https://github.com/infituit/opencode-acp/issues/51).
