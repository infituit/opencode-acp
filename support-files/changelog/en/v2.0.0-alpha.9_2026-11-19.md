## [Version: v2.0.0-alpha.9] - 2026-11-19

Full Changelog: [v2.0.0-alpha.8...v2.0.0-alpha.9](https://github.com/infituit/opencode-acp/compare/v2.0.0-alpha.8...v2.0.0-alpha.9)

**Release scope**

- An ACP 2.0 Alpha maintenance update improving catalog recovery, diagnostics, and fallback warnings when the model context window is unknown.

**Fixes**

- Fix catalog hydration being attempted only once on a miss. Later requests can retry; concurrent requests share an in-flight load, with a 30-second cooldown after completion to avoid catalog requests on every turn for unknown models.
- Add catalog diagnostics distinguishing unavailable APIs, malformed responses, request failures, empty catalogs, and entries without valid context limits. Log entry counts without raw responses or exception text.
- Correct missing-window warnings to distinguish an active `compress.contextLimitFallback` from a disabled fallback, rather than incorrectly claiming that all related checks are disabled with the default fallback.
- Document fallback configuration and budget risks, and correct the bug report template’s OpenCode V2 compatibility statement.

**Compatibility and upgrade prerequisites**

- Requires **OpenCode >=2.1.4 and <3**.
- No new configuration options or dependencies, and no changes to persisted state formats. Upgrading from alpha.8 requires no data migration.
- `compress.contextLimitFallback` still defaults to `128000`; set it to `0` to disable it. Once the actual model window is recovered, related thresholds use that window.

**Known issues**

- This release does not change summary citation-fidelity gates or guarantee resolution of every repeated evidence-retrieval loop reported in [#60](https://github.com/infituit/opencode-acp/issues/60).
- A fallback does not increase the model’s actual capacity. Custom models should have an accurate OpenCode `limit.context` configuration.
