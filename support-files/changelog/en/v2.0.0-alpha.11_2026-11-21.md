## [Version: v2.0.0-alpha.11] - 2026-11-21

Full Changelog: [v2.0.0-alpha.10...v2.0.0-alpha.11](https://github.com/infituit/opencode-acp/compare/v2.0.0-alpha.10...v2.0.0-alpha.11)

**Release scope**

- An ACP 2.0 Alpha file-protection maintenance update fixing incomplete recognition of V2 file-tool parameters when `protectedFilePatterns` is configured.

**Fixes**

- Recognize file tools’ `path` parameter while retaining existing `filePath` and `multiedit` extraction, so matching files participate in existing compression filtering, protected-range guidance, and tool-output preservation.
- Recognize `patch.patchText` while retaining `apply_patch` support. Include added, updated, deleted, and move-destination paths in protection checks, alongside move-source paths.
- Avoid interpreting operation-header-like text in added patch content as file paths.

**Compatibility and upgrade prerequisites**

- Requires **OpenCode >=2.1.4 and <3**.
- No new configuration options or dependencies, and no changes to glob matching rules, persisted formats, message refs, or compression block IDs. Upgrading from alpha.10 requires no data migration.
- File protection still requires matching `protectedFilePatterns`; it is not enabled by default and does not automatically restore already-compressed messages. Previously missed matching messages may no longer enter compressible ranges after upgrading.

**Known issues**

- This release only fixes shared path extraction. It does not change OpenCode native compaction or other compressors.
- This release does not include the image/base64 or decompression-budget fixes discussed in [#51](https://github.com/infituit/opencode-acp/issues/51), nor eliminate all long-history scanning or delays.
